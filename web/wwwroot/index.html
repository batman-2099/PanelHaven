      Server settings

      Back to library

      These are saved server settings, not browser preferences. Application, library, network, TLS, and secret changes take effect only after restart. Backup scheduling is applied when saved; check its actual status below.

      Running configuration and recovery paths

      Running values below do not change when you save a restart-required setting. Recovery files are private server files; if a network change locks you out, restore the prior settings file on the server and restart.

      Libraries

      Comic Vine

      Leave a secret blank to keep it, enter a replacement to set it, or explicitly select Clear to remove it. Existing secrets are never displayed. Secret changes require restart.

      Network and TLS

      Trust only proxies you control. Listen URLs are server bindings, not necessarily browser addresses. Changing the protocol, host, port, or certificate can disconnect you after restart. Make sure the new address and HTTPS/proxy setup work before restarting.

      Scheduled backups

      Scheduled backups contain the database and data-protection keys only. They do not include comicbooks, the comicbook-backup vault, or this server settings file. Back up those separately. Scheduling requires Linux user systemd; a saved schedule is not proof that its timer is active.

      Service and startup

      Startup controls install or update this installation's owned Linux user service. They do not apply unsaved edits or immediately restart the application. Availability after a reboot also depends on your user service manager and login/lingering configuration.

      After restarting, reconnect manually at the saved address (or your reverse proxy address). This page will not redirect or retry a restart automatically. Wildcard bindings such as 0.0.0.0 or * must be replaced with the server's reachable hostname.

      Data location

      Data relocation is separate from configuration saving. It copies all application state, including the database, keys, and comicbook-backup vault, on the next startup. Comic libraries stay where they are. The original data is preserved for recovery.

      Export comics

      Downloads supported page images in saved page order with shared catalog metadata, including custom values and embedded page metadata. No private reading progress, ratings, bookmarks, lists, or preferences are included. Original files, catalog, and access permissions remain untouched.

      One book downloads as a CBZ; multiple books download as a ZIP containing CBZs. Up to 100 books and 1 GiB per download. The complete file is prepared and verified on the server before transfer, then received by your browser before saving. Allow enough free space. Closing this dialog or pressing Escape cancels an active download.

      Library maintenance

      Comicbook original backups

      Export originals for every book, including books removed from the catalog. The unencrypted ZIP contains complete original comicbooks and manifests, including sensitive private paths. It can be large. Application state is excluded: protect this ZIP separately and keep it with an application-state snapshot.

      To recover backups, restore a trusted export's archive-backups directory into the stopped application's state directory alongside its matching state snapshot. Keep directories private (0700) and files private (0600) on Linux. Export does not import or delete anything.

        Review exact changes

        Write metadata to comicbook

        Only CBZ/ZIP sources support write-back and restore; other formats remain read-only. Preview checks the source and saved catalog metadata. Nothing is written until you explicitly confirm and apply. A write keeps a verified complete original comicbook backup first.

        Writing may change XML formatting/encoding and ZIP compression, but keeps non-metadata entry contents. Stop other programs from changing this source: portable file APIs cannot atomically coordinate with noncooperating external writers.

        Restoring replaces the whole comicbook with the selected original bytes; it does not undo catalog metadata edits. Book identity, private progress, ratings, bookmarks, and list memberships stay unchanged. Comicbook backups are retained separately, are never automatically deleted, and their payloads are excluded from application-state backups.

          Destination templates

          Tokens: {Series}, {Year}, {Number}, {Title}, {Publisher}, {Volume}, {FileName}. {FileName} is the original filename without its extension. The server appends the unchanged source extension. For a simple bulk move, keep {FileName} and choose a folder; blank folder means the root. Use / between folders. Missing metadata, unknown or malformed tokens, unsafe values, and invalid paths are conflicts, never silently sanitized.

          Smart rules

          Smart lists update automatically as metadata, your reading progress, and private ratings change. Use 1–20 total rules in at most 20 groups and 4 levels (including this root).           Private list folders

          Organize private lists in nested folders. Deleting a folder unfiles only its direct lists and moves its immediate child folders to the top level, keeping their contents. No lists, books, or private reading data are deleted.

          Relocate application data

          The server validates the destination before queuing a move for the next startup. Its parent must already exist, but the destination itself must not exist. Use a separate absolute path outside library roots, application files, settings, and the current data directory; symlinks and overwriting existing contents are not allowed. Allow enough free disk space for the complete copy. The source is preserved. A failed copy keeps the old data location active.
